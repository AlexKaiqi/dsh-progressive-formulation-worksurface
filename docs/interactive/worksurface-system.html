WorkSurface 的用户价值

把复杂目标，变成可以持续推进、独立验收、按依赖协作的工作单元

这就是 WorkSurface。 它不替代 AI 执行，也不把聊天画成流程图；它让“正在完成的工作”拥有独立于某一次对话的结构、材料和进展。

1

一个复杂目标，先成为一个持续存在的 Surface

示例：用户要求完成一份可发布、结论可核验的市场研究报告。

用户的复杂目标 完成市场研究报告

需要资料来源、数据核验、观点形成和最终成稿；一次对话很难可靠承载全部工作。

→
Surface · 工作本体

市场研究报告

不只是一个目录，也不是一段聊天；它是这个工作单元的持续身份。

目标验收条件材料决策产物
唯一绑定的 DSH Session AI 围绕这个工作单元的完整执行历史

关系：Surface 说明“这项工作是什么、现在有哪些内容”；DSH Session 记录“AI 为它做过哪些思考、模型调用和工具执行”。两者 1:1 绑定，但不是同一个东西。

2

当部分工作需要独立验收，它们成为各自的 Surface

不是为了画一棵漂亮的任务树，而是为了给每项工作独立的目标、材料、执行历史和完成标准。

Agent 规划出三个可独立验收的 Surface；其中前两项可以并行推进

Surface A

资料研究

收集并整理可引用的一手资料。

独立验收：所有核心论点都有可追溯来源。

DSH Session A专注资料研究的 AI 执行历史
Surface B

数据核验

检查统计口径、计算过程和关键数字。

独立验收：关键数据可复算，口径与来源一致。

DSH Session B专注数据核验的 AI 执行历史
3

Orchestrate 用明确依赖决定下一项工作何时开始

参与的 Surface 已由 Agent 创建，并被当前 Registration 绑定。事实成立后，Orchestrate 按普通代码把必要信息写入目标 Surface 的可寻址内容，再触发它继续推进。

资料研究通过sources.ready
数据核验通过data.verified
两个独立事实共同进入同一条依赖规则
Orchestrate · 明确依赖 两项事实都成立

才允许“报告成稿”开始推进

→
Surface C

报告成稿

消费已经通过验收的资料和数据，形成最终可发布产物。

独立验收：结论与证据一致，满足发布标准。

DSH Session CRuntime 按 Orchestrate 的 advance 请求推进，负责实际写作与工具执行
Surface = 工作单元

保存目标、验收条件、材料、决策和产物；一次 Turn 结束后仍持续存在。

DSH Session = 执行者的历史

承载模型、Turn、Step 和 Tool Call；每个 Surface 当前唯一绑定一个 Session。

Orchestrate = 工作单元之间的关系

通过 Registration 绑定已有 Surface；根据明确业务事实传递或更新上下文，再推动目标 Surface 继续，不负责创建 Surface。

上下文筛选、可靠重放和受管 Operation 是 Runtime 的确定性工作，不是模型和用户理解 WorkSurface 产品价值的前置负担；这些边界由设计基线、JSON Schema 与测试定义。
