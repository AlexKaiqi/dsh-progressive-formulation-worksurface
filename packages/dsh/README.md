# @pf-worksurface/dsh

DSH 集成层装配 file event store、content-addressed RevisionStore、Registration reconcile、Session/Turn adapter 与 Host RPC。公开领域只使用 Surface、Orchestration、Registration、Revision 与 Event；执行直接复用 DSH 的 Session、Turn 和 Step，不建立第二套执行身份。

Surface 开始推进前一次性绑定唯一 DSH Session，并固定 inputRevision 与 expectedHead。权威绑定只写入 `surface-sessions/<surface-id>/binding.json`；新绑定不再把冗余的 `worksurface/binding` 私有事件写入 DSH Session，旧日志中已有的同名事件仍会只读校验。只有 live Session 与 persistence 两侧都支持持久 `ignorable` envelope 时，才启用基于 extension facts 的 Context Runtime；旧 Host 的稳定兼容面是 Turn Brief、四个 shell 变量和外部 immutable binding。Session workspace 是公共作者根，当前 Surface WIP 由 `surfaces/<surface-id>/` 精确定位。后续 Turn 自动继续该目录，不能改变 Session 绑定；Turn 关闭或被中断时，其短期 capability 失效。发布时只 snapshot 当前 Surface 目录，再做 CAS；冲突保存 outputRevision 并记录 `surface.publish.conflicted`。

启动恢复把 `sessionPersistence` 作为必需装配依赖，重放唯一绑定、publication Event 和 Session 日志，修复可丢弃的 authoring checkout，并从全部 Surface/Registration Event 与 binding 发现 Revision GC 根。`workspaceRegistry` 同样是必需依赖：公共作者根注册为真实 DSH Workspace，每个创建或恢复的 Surface Session 在返回 Web 前完成 attach，使尚无首个 Turn 的空白 Session 也能由原生导航打开。冷 Session 的最后 Turn 若由 persistence 标记为 `interrupted`、由 DSH 以 `aborted/disposed` 关闭，或 inbox 仍有持久 `next-turn`，Host 会恢复同一 Agent/Session 并提交一条插件来源的保守续推；已完成、等待用户、普通空闲或尚未物化出持久日志的空白 Session 不会被唤醒。单个损坏 Session 或 Registration 会记录警告但不会阻塞其余启动恢复；每次启动记录恢复与 reconcile 计数。Event 未引用的旧孤儿 Revision 可以回收；作者目录中的持久 WIP 保守保留，只清理超过 retention 的临时 materialization；升级前已绑定 Session 的不可变旧 cwd 继续兼容其私有 WIP，所有新绑定只使用公共作者根。

所有普通 Agent 都收到精简的 WorkSurface 能力发现说明，并在模型 shell 中获得公共 `DSH_WORKSURFACE_ROOT` 与稳定的 `DSH_WORKSURFACE_CLI`，因此可以运行 `"$DSH_WORKSURFACE_CLI" help` 后用普通文件能力 author 首个或后续 Surface；不能假设 profile `.bin` 已进入 `PATH`。DSH 的 persistent shell 组合若没有把 `shellEnv` overlay 传入 PTY，adapter 的兼容说明要求模型使用当前 authoring cwd 与 PATH 上的 `ws`，不得猜隐藏路径；这不等价于变量注入，必须由 profile E2E 单独验收。操作细节按 `author`、`coordinate`、`emit`、`recover` 场景读取，不常驻 prompt。Surface Session 创建时的 cwd 是公共作者根；每个活动 Turn 额外注入 `DSH_SURFACE_ID`、`DSH_SURFACE_DIR`、`DSH_WORKSURFACE_VIEW_DIR`，并从 View 目录读取 `turn-brief.json`。对于不消费 `shellEnv` 的 persistent PTY，adapter 在 `system-prompt/assemble` 阶段动态追加当前 Turn 的精确目录、Brief、authoring root 和 CLI locator；变量与动态 locator 都缺失时，模型必须停止并报告宿主注入失败，不能猜路径。模型不能 `open` 或切换当前 Session 绑定。Brief 的精确 emit argv 是唯一模型侧领域命令；Runtime 在 append root fact 前校验完整目录并固定尚未登记的 `registration.json`，随后按 code-first Registration route 推进。执行状态、等待输入、模型调用失败和重试由这个 DSH Session 的 Turn/Step 事件表达。

原生 WorkSurface UI 通过 Host admission 确保 Surface 的 Session。首次进入使用 `ctx.agents.create()` 的 unpublished setup 组合默认 Agent preset、写入唯一 binding，并把公共作者根作为 Session cwd；它发布一个尚无 Turn 的空白 Session，不替用户提交消息。admission 返回前会完成 Workspace attach 与原生 Session flush，使旧 persistence 也能在浏览器刷新后重新发现该空 Session。再次进入同一 Surface 返回 live Session，或经 DSH persistence 恢复同一 SessionId，绝不创建第二个执行身份。

默认 code-first Registration 固定 artifact Revision、bindings、Contract routes 与首次 admission 历史边界；Input Ledger 和两阶段 Operation Ledger 支持重启补收与 record/apply/settle 恢复。managed followup 会 admission 未绑定目标或恢复冷 Session，并在 Session flush 证明 durable user/message receipt 后才写 settlement，而不等待整个 Agent Turn。公开作者目录保持平铺；私有 streams、revision objects、binding/context、socket 和 capability 不进入该布局。`v4/` Definition/Activation/Operation 是兼容路径；默认 Runtime 事实进入 `v5/`，旧 `v2` 与多对多 `v3` 数据只读报告，不自动迁移或删除。
